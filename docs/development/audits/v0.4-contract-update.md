## 本轮完成范围

按[主线](../design/v0.4.x-mainline.md)并行推进风险修复与
[真实 AI 使用观察](v0.4-ai-observation.md)。没有实现 runner、配置文件解释 API、
完整 schema 或新的业务发布协议。0.4.1 的首项有界改善是
[短自动化入口](../../automation.md)。审查后已用冻结候选完成
[Caddy 实际 AI 观察](v0.4-caddy-ai-observation.md)；三个有效条件均未调用 ToolX，
不能据此宣称修复或资料降低了模型核验/修复成本。

| 问题 | 当前实现 | 主要验证 |
| --- | --- | --- |
| 旧 trace 存在消失路径、append 错位 | 来源随合并传播，最终树按真实路径/索引归因；空容器和转义键一致 | cfgx 既有测试＋7 个新反例 |
| sync 失败清空事实 | 验证/编译失败保留已合成上下文；真实发布后保留 execution 和恢复报告 | schema/runtime/第二写 I/O 黑盒合同 |
| resultx 吞掉 failed RunResult | 失败 value 仍含完整 fsx 报告 | partial execution adapter 回归 |
| rolled_back 误报、计数单位混淆 | attempt/complete/error 分开；Run 按实际业务步骤计数，恢复按 undo record | 跳过、部分失败、Strict/BestEffort、独立与依赖路径 |
| 更新既有 target 暂时消失 | 单次原生替换，已有读者保留旧内容，新打开路径为新内容 | 持有读者、sharing violation、发布前后崩溃 |
| 原子覆盖与旧恢复记录不匹配 | 显式 FSXJ4 checked REPLACE＋RESTORED，仍读取 J1–3 | 崩溃、恢复重试、marker 写失败、foreign target/witness |
| 提前退出丢失 JSON 模式 | sync help/parse error 保留 JSON 选择，完整解析仍尊重真实 option/value | 参数顺序、`--` 值、字面 `--json` 值 |

来源修复仍只承诺 layer 级别，不含 overlay 文件名。多个 local 文件仍合成 local；
没有把已有正确性修复包装为新的可解释配置产品。

## 独立审查后的追加收口

两名独立审查者分别检查恢复状态机和配置/CLI 契约，先保留反例再修复。
审查发现的实际错误继续按风险处理，没有以“既有问题”为由豁免错误成功：

| 反例 | 修复及独立验收 |
| --- | --- |
| `--out` 与 journal 同路径，返回成功却追加 COMMIT；库默认清理还会删除产物 | Run 写 header 前检查所有 batch 源、目标树与保留 backup；覆盖规范路径、祖先关系、硬链接与 Windows Unicode 大小写，拒绝时零步骤、原文件不变 |
| 新文件相对路径 journal 换 cwd 后恢复，误报 complete 并删除日志 | 新 J4 undo 路径持久化为绝对路径；解析阶段拒绝相对 J4；分别测试新建/覆盖目标、换 cwd、证据保留与重试 |
| 合法空 JSON key 的 overlay 清空邻居 trace | 新增此前无效的 `[]` 空对象键 path 表示法，与字面 `\[\]` 区分；Get/Set/Remove、trace 最终树和 reload diff 对照 |
| 先合并多个 overlay，再作用于 base，复活已被 scalar 替换的子树 | 按真实输入顺序逐层合并，保留此前真实 layer；对象→scalar→对象与 append/replace、来源同步验收 |
| JSON `1e999` 生成 `inf` 并报告验证通过；NaN range 绕过范围检查 | JSON grammar 和可表示有限值检查；CLI 错误 range 返回 usage，API range 拒绝非有限边界/值；不生成产物 |
| Double 默认六位有效数字造成数值损失，locale 可改变 JSON 数字格式 | classic locale、max_digits10、积分 double 的 `.0`；最小 subnormal、最大值、负零、精确值与自定义 locale 往返 |
| 早退 JSON 探测仍把 option value 当作 flag | 注册参数时同时记录需值的 option，fallback 尊重取值和 `--`；不另维护一套人工 option 清单 |

这些是可见兼容变化：依赖错误 overlay 预合并行为的流程会得到纠正后的不同结果；
非法或不可表示的数字现在拒绝；空键 grammar 是加法；double 文本可能增加有效位与
`.0`，而值及类型得到保留。新 J4 尚未发布，因此本轮早期探索生成的相对路径 J4
不作为兼容格式接收。历史 J1–3 保留读取，但相对记录必须在原 cwd 恢复；该格式
没有 origin，给绝对 journal 文件名不能推断其旧工作目录。详细边界仍以公开指南为准。

本轮不宣称完整 JSON 标准实现：Unicode/重复键等既有有界解析行为没有全面重写，
程序构造的非有限 Node 仍需调用者在 ToJson 前拒绝。路径隔离是独占工作区中的静态
检查，不是并发 writer sandbox 或 CAS。原始审查探针在 `temp/v041-review-contracts`
与 `temp/v041-review-recovery`，不覆盖或替换前一轮冻结观察证据。

## 第三轮独立审核：悬空链接不能作为普通新路径

TX04-R3-001（P2）采纳，属于既有日志安全契约的残留。R2 对实际 `.1`–`.5`
命名空间的直接路径与有效别名检查仍有效，但不能据此整体关闭日志安全：
weakly_canonical 对尚不存在的链接目标保留未解析后缀，equivalent 也无法确认
两个尚不存在目标的身份。journal 链接到不存在的主 log、`.1` 或 `.5` 时，后续
写 header 与日志追加/轮转会跟随链接，出现成功后 journal 被追加 INFO、替换为
旧 log 或删除。反向 log 链接到尚不存在的 journal 同样可污染 COMMIT。

本轮选择有界的 fail-closed 行为，不新增自定义符号链接解析器。在配置了 log 时，
先逐组件检查主 log、实际 archives 与所有受保护路径；已有符号链接的目标不存在、
无法查询或类型未知便 usage 2 拒绝，之后才进行既有 canonical/equivalent/祖先
比较。检查不创建路径，不先 lexically_normal 消去原路径组件。普通新路径仍支持，
可解析的有效链接保留支持；不改变无 log 时的 journal 行为，不增加并发保证。

组件审核还实证了同一边界的变体：log 为 `new-dir/../journal-link.log`，该 link
指向尚不存在的 `run.journal`。若 out 是普通 `out.json`，FileSink 不会自己建目录，
旧候选虽成功但 journal 没有污染；不能将这一对照误算为破坏反例。若 out 改为
`new-dir/out.json`，fsx 发布建立父目录，成功日志的 FileSink reopen 才跟随原路径
追加 INFO 到 COMMIT 后，复用失败。因此检查遇到缺失组件之后的 `..` 也 usage 2
拒绝，不用归一化字符串推测未来创建目录后的别名。普通缺失后缀仍支持。

这是明确的兼容收紧：即使分离的 dangling journal 当前不会与 log 冲突，只要配置
了 log 也拒绝。调用者可先建立有效 journal 目标，或在不需要日志时沿用原行为。
该成本优于为了保留这项边界用法再维护一套链接链、缺失目标与平台解析规则。
新增反例和正常对照、冻结候选及相关门禁单独记录在 `temp/v041-r3-*`；R1/R2 和
AI 观察证据不覆盖。此修复不算新增能力或采用成本下降的证据。

本轮仅 `tools/toolx_sync.cpp` 和 `cmake/toolx_sync_cli_scenario.cmake` 相对 R2
变化；134 项构建输入的冻结 manifest SHA256 为
`db806c3250215ae8f5bc3370a4fb91009dfbf46b1523c2312dc60b1a5095ac36`。
回归增加 22 个拒绝场景及 3 组首发/复用对照；拒绝必须保持完整目录清单、文件
SHA 和 link target 不变。满阈值/正常轮转等原 R2 场景继续执行。

## 第四轮独立审核：Windows 显式数据流别名

## FSXJ4 的必要成本与边界

FSXJ3 的 REMOVE/MOVE 记录无法区分单次覆盖前后的内容状态。为了修 target 路径
可见性而仍能恢复，本轮显式增加新 header 和 REPLACE/RESTORED，不在旧 header 下
偷偷扩语法。旧工具拒绝新 header；新工具保留 J1–3 读取。恢复完成前应保留产生日志
的工具版本。这是本轮实质兼容成本，不能称为零迁移修复。

每次覆盖保留旧/新两份私有 witness，以及候选和恢复 staging。通过原生 file identity、
大小、写入/变更时间检测普通 witness 修改，再对 target 与 witness 精确逐块比较。
恢复进度同步成功后才清理 witness；失败保留依赖证据。相同内容视作等价，不声称
对敌对元数据伪造、并发 writer CAS、完整 ACL 保真或断电持久性提供保证。
完整规范在 [fsx 指南](../../modules/fsx.md)，不另造一份机器协议事实源。

POSIX 使用同目录 rename；C++ 的 [rename 规范](https://eel.is/c++draft/fs.op.rename)
定义为 POSIX rename。Windows 使用支持替换且保留打开读者的 FileRenameInfoEx
POSIX semantics，依据 [Microsoft 原生语义](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information)。
系统/文件系统不支持时返回失败，不回退到两次 rename 的缺口路径。已有目录和
有效/悬空符号链接都拒绝，不以 exists 跟随链接后的结果判断目标是否存在。

独立审查还发现并修了 malformed COMMIT 日志会被新 Run 静默覆盖的问题。
共享私有只读解析器服务恢复与重用检查，先验证完整记录再决定是否可复用；不调用
带副作用的恢复过程当 validator，也不匹配英文错误消息决定状态。
