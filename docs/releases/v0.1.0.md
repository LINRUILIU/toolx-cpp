# ToolX v0.1.0

> Audience: ToolX users and package consumers
> Status: Historical release note
> Applies to: `v0.1.0`
> Source of truth for: user-visible v0.1.0 release narrative

## Highlights

- First productized ToolX library release.
- Stable core baseline for `argtool`, `cfgx`, `asyncx`, `fsx`, `logsys`,
  `resultx`, `utils`, `sysx`, `hashx`, and `textcodec`.
- Bounded `httpx` and experimental `tuix` foundations.
- First formal `toolx-config` JSON/exit-code contract and `doctor` workflow.
- Scenario-oriented `toolx-sync` introduced before its later product admission.

## Compatibility

The release targeted documented source compatibility inside `0.1.x`. It did
not promise ABI compatibility across compiler, standard library, or build
configuration boundaries.

## Build and dependency impact

HTTPS behavior depended on the selected `httpx` backend. Consumers used the
exported CMake package targets; TLS backend choice remained build-time policy.

## Migration

This was the first formal line. New integrations were expected to use the
documented CMake targets and the `toolx.config.result` version-1 envelope.

## Known limitations

- `tuix` was not part of the main stable pitch.
- `httpx` TLS capability depended on build configuration.
- No ABI guarantee was provided.
