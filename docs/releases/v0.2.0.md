# ToolX v0.2.0

> Audience: ToolX users and package consumers
> Status: Historical release note
> Applies to: `v0.2.0`
> Source of truth for: user-visible v0.2.0 release narrative

## Highlights

- Added experimental `schemax` compilation/validation on top of `cfgx`.
- Added schema validation to `toolx-config` and `toolx-sync` with exit code `4`
  and additive `schema_issues` output.
- Expanded `tuix` with styled cells, themes, layouts, panels, text input,
  lists, and a config-inspector example.
- Added `asyncx` cancellation, task options, deadlines and task groups.
- Added `fsx` directory diff/sync and deterministic tar support.
- Added `httpx` retry, circuit breaker, safe download and multipart upload.
- Added `logsys` context, trace spans and metrics.
- Added 13 annotated module cookbooks and cookbook smoke tests.

## Compatibility

The changes were additive relative to v0.1.0. Stable APIs continued the source
compatibility goal; `schemax` and `tuix` remained experimental. No ABI promise
was introduced.

## Build and dependency impact

The installed package added `toolx::schemax`. Test-enabled configurations built
the new cookbook smoke coverage. HTTPS still depended on the selected backend.

## Migration

Existing consumers required no source migration. Consumers using the new
schema surface needed to link `toolx::schemax` in addition to `toolx::cfgx`.

## Known limitations

- `schemax` was a bounded subset, not full JSON Schema.
- `fsx` archives were tar-only.
- `tuix` remained an experimental application foundation.
- ABI compatibility and backend-independent HTTPS were not promised.
