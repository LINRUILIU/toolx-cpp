ToolX `v0.3.0` finalizes the first CLI product chain.

`v0.2.0` established the single-tool stable product baseline with
`toolx-config`. The `0.2.x` development line added the remaining bounded-stable
CLI products. `v0.3.0` turns that work into the documented release set.

## Product CLIs

- `toolx-config`: primary config authoring and review contract.
- `toolx-sync`: config composition and atomic publish workflow.
- `toolx-pack`: local staging and deterministic tar packaging.
- `toolx-http`: runtime endpoint preflight for release and deployment gates.
- `toolx-log`: offline runtime log diagnosis and lightweight log gates.
- `toolx-inspect`: config/schema inspection through stable reports,
  deterministic render output, and scripted terminal runs.

Each product CLI has stable exit codes, a `schema_version=1` JSON envelope,
black-box contract coverage, install-tree smoke coverage, packaged archive
smoke coverage, and standalone documentation.

## Stability Boundary

Stable core modules remain source-compatible through the `0.3.x` line unless a
safety or correctness bug requires a breaking change. ToolX still does not
promise ABI compatibility across compiler, standard library, or build
configuration boundaries.

`schemax` remains an experimental MVP layered on `cfgx`. `httpx` remains
bounded by TLS backend configuration. `tuix` remains an experimental foundation;
`toolx-inspect` stabilizes only the bounded config/schema inspection workflow,
not a general TUI framework.

## Release Readiness

The release is suitable for tagging after the standard gate passes on `main`:
format check, full build, full CTest, install-tree smoke, install consumer
build, CPack binary archive, unpacked archive smoke, and the GitHub Actions
matrix.
