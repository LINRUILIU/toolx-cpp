# ToolX v0.3.0

> Audience: ToolX users and package consumers
> Status: Historical release note
> Applies to: `v0.3.0`
> Source of truth for: user-visible v0.3.0 release narrative

## Highlights

v0.3.0 finalized the first ToolX product chain:

- `toolx-config`: config authoring and review;
- `toolx-sync`: composition and atomic publish;
- `toolx-pack`: local staging and deterministic tar;
- `toolx-http`: endpoint preflight;
- `toolx-log`: offline runtime-log diagnosis;
- `toolx-inspect`: config/schema reports and bounded terminal inspection.

Each tool entered the installed package with black-box contract coverage,
install-tree smoke, archive smoke, stable exit codes, a version-1 JSON envelope,
and standalone documentation.

## Compatibility

Stable modules and tested CLI fields entered the documented `0.3.x`
source-compatibility line. Existing tested JSON fields became additive-only.
`schemax` and `tuix` remained experimental; `httpx` remained bounded by TLS
configuration.

## Build and dependency impact

The install and CPack archives included all six tools. Standalone consumer and
unpacked-archive verification became release gates. Default packages still did
not select a TLS backend.

## Migration

v0.2 consumers required no library source migration. Scripts could adopt the
new product-specific schemas instead of treating scenario output as shared.

## Known limitations

- The product chain was not a deployment or package-management platform.
- HTTPS remained backend-dependent.
- `toolx-inspect` did not stabilize `tuix` as a general framework.
- ABI compatibility was not promised.

See the [0.3.0 productization retrospective](../development/retrospectives/productization-retro.md).
