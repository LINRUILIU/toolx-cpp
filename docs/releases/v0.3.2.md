# ToolX v0.3.2

> Audience: ToolX users, package consumers, and release reviewers
> Status: Released
> Applies to: v0.3.2
> Source of truth for: release narrative

Release date: 2026-09-14.

## Highlights

### Deterministic proxy control

- `toolx-http check` adds `--no-proxy-from-env`; manifests may set
  `use_proxy_from_environment`.
- `toolx-sync` adds the same opt-out for `--remote-url` requests.
- Both JSON contracts add the additive `data.proxy_from_environment` field.

### FSXJ3 recovery ordering

- Configured `fsx` journals use synchronized FSXJ3 write-ahead undo records
  before destructive primitive mutations.
- Header, undo records and `COMMIT` are persisted before normal cleanup.
- Recovery does not overwrite a destination that appeared after the journal
  entry; it reports a conflict and preserves evidence.
- FSXJ1 and FSXJ2 recovery remain supported.

### TLS and documentation verification

- CI adds a dedicated Linux/OpenSSL loopback TLS test using a temporary key and
  certificate, trusted localhost verification, and hostname-mismatch rejection.
- Public documentation is reorganized into architecture, module, CLI, build,
  dependency, stability, roadmap and reproducible showcase layers.

## Compatibility

This release preserves the documented `0.3.x` source and additive CLI
boundaries. No public target, API, command, exit code or existing JSON field is
removed or redefined.

## Build and dependency impact

Default builds and release packages remain free of a TLS backend dependency.
The real TLS job is an additional CI configuration only. Documentation checks
use CMake script mode and add no runtime dependency.

## Migration

No public API migration is required. Callers relying on linked tree descendants,
overlapping staging roots or invalid HTTP metadata must correct those inputs;
they now return errors. Automation that needs deterministic direct or loopback
routing should opt into `--no-proxy-from-env`; existing default proxy behavior
remains unchanged.

## Known limitations

- FSXJ3 improves recoverable ordering but does not claim universal power-loss
  atomicity across filesystems, drive caches or cross-device moves.
- The OpenSSL job proves loopback trust/hostname behavior, not interoperability
  with arbitrary external HTTPS services.
- mbedTLS remains supported by a CMake path but is not verified by current CI.

## Security hardening

- Tree operations reject linked descendants and unsafe relative entry names.
  New copy parents use valid FSXJ3 staging records for crash recovery; type changes
  roll back correctly and external conflicts preserve the journal.
- HTTP rejects unsafe request targets, header/multipart controls, blank Host values
  and ambiguous Content-Length/Transfer-Encoding framing. Relative redirects retain
  the correct base path and query; fragments are omitted from wire targets.
- Multipart boundaries use random values and at most eight collision checks.
  Collision and exhaustion paths are covered by deterministic tests and fuzz input.
- Pack rejects overlapping source/stage roots, removes obsolete entries before
  copying replacements, preserves legitimate backup-like names, and reports
  enumeration failures. Native POSIX include/exclude paths retain literal names;
  tar member names continue to follow stricter portable rules.
- Release metadata and source archive checks fail closed. Documentation must be
  consistent across README, CHANGELOG and release notes before publication.
- Loopback startup failures and clang-tidy findings block CI. ASan/UBSan and
  bounded cfgx/httpx/fsx fuzz runs supplement the suite. Coverage XML/HTML artifacts
  are checked explicitly and uploaded using OIDC authentication. The coverage gate
  retains the existing 70% line and 40% branch floors.
- A scheduler deadline reference invalidated by concurrent task removal/reallocation
  is fixed by owning a deadline copy across the timed wait.

Public signatures are unchanged. Previously accepted unsafe metadata and linked
tree entries now return errors. Caller-owned roots must remain stable during
operations; these changes do not claim race-free filesystem sandboxing.
