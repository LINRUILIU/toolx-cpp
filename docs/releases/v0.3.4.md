# ToolX v0.3.4

> Audience: ToolX users, package consumers, and release reviewers
> Status: Released
> Applies to: v0.3.4
> Source of truth for: release narrative

Release date: 2026-10-22.

This maintenance release repairs existing data-preservation, HTTP, validation,
cancellation and logging contracts. It keeps thirteen library targets and six
CLI products. It does not resume the stopped v0.4 product work.

## Highlights

- Decode JSON Unicode escapes into UTF-8, preserving BMP characters, surrogate
  pairs and distinct object keys. Escape all C0 controls on serialization; reject
  unescaped controls and malformed or unpaired surrogates on parsing.
- Reject archive destinations that alias source data, including unresolved
  symbolic-link paths. Extraction with `Skip` preserves existing entries while
  consuming skipped payload and padding, so subsequent entries are still read.
- Check pack/inspect audit destinations and actual size-rotation paths against
  protected inputs before initializing file logging. Pack also separates archive
  and journal destinations and checks output conflicts during plan/dry-run.
- Create download temporary siblings exclusively. Existing temporary paths and
  their data remain intact on failure. Followed redirect bodies do not reach
  download bodies, stream callbacks or progress; the effective per-request
  redirect policy is propagated on every hop, including when it overrides a
  client default that disables following.
- Handle empty HTTP header blocks, bodyless 204/304 responses and up to sixteen
  informational responses. Reject protocol switching instead of treating it as
  an ordinary response body.
- Apply supported `additionalProperties:false` even without a `properties`
  block. Reject negative or unrepresentable min/maxLength bounds at compilation.
- Join group and per-task cancellation dynamically. After a wait, every accepted
  TaskGroup task is classified as completed, cancelled or failed, including work
  skipped or discarded before execution. Explicit logger flush visits every
  configured route and flushes a shared sink once.
- Match multi-config build and test presets at Debug and document matching
  Release overrides.

## Compatibility

These are correctness exceptions under the [stability policy](../stability.md).
Documented public source signatures, CLI command and exit-code sets and existing
JSON envelope fields retain their shape. JSON remains at `schema_version=1`.
Safer path checks and corrected parsing, callbacks, validation and statistics
change behavior that callers could previously observe.

**Rebuild C++ consumers against the matching headers and libraries.**
`CancellationToken` has a changed private layout to retain joined cancellation
sources; TaskGroup's internal outcome tracking also changes. Source compatibility
does not imply ABI compatibility or safe mixing of old objects with new libraries.

FSXJ4 is unchanged in this release. The producer-version, witness-space and
recorded-location requirements introduced in [v0.3.3](v0.3.3.md) still apply;
older binaries that reject FSXJ4 do not gain compatibility by editing its header.

## Build and dependency impact

C++20, CMake requirements, thirteen exported library targets and six installed
CLIs are unchanged. No new dependency is introduced. Default packages select no
TLS backend; OpenSSL and mbedTLS remain optional and mutually exclusive.

The dev and clang-tidy build/test presets select Debug for Visual Studio and
other multi-config generators. Use `cmake --build --preset dev --config Release`
with `ctest --preset dev -C Release` for Release. Single-config generators still
use configure-time `CMAKE_BUILD_TYPE`.

Independent functional verification dated 2026-10-22 recorded Windows/MSVC full
CTest 44/44, Linux HTTP sanitizer tests 61/61, and Linux OpenSSL HTTP tests 63/63.
These results retain their exact source identities and scope; they are not a
claim that pending hosted jobs or final versioned packages have passed. Hosted
validation, installation, archives and publication completion are established
by the workflows for the final release commit. Privilege-dependent skips remain
distinct from executed cases.

## Migration

1. Rebuild C++ applications and libraries that consume ToolX; do not combine old
   object files with the new cancellation-token layout.
2. Review escaped Unicode values, object-key lookups and JSON text baselines.
   Previously replaced characters cannot be reconstructed from already damaged
   output. Recover such values from a trusted original. Replace malformed
   surrogate escapes and literal controls with valid JSON; serialized controls
   now use legal escapes.
3. Use separate ordinary paths for business data, logs and their rotation
   archives, archive outputs and retained journals. Pack/inspect conflicts are
   usage error `2` before writes; plan/dry-run also reject pack conflicts.
   Windows stream archive/log paths are refused. Native filesystem case,
   hardlink and symbolic-link aliases can also trigger rejection.
4. Inspect any stale download `.part` file before removing it, or choose an
   unused sibling suffix. Temporary suffixes must be non-empty and cannot name
   another directory. Existing temporary paths and Windows stream paths are
   rejected; retries reset only the exclusively owned temporary file. This is
   not automatic resumption of an earlier partial download.
5. Expect only the final followed response in bodies and callback/progress
   streams. Per-request following overrides the client default on every hop.
   A response intentionally not followed still delivers its own entity. Servers
   relying on bodies for 204/304, protocol switching or more than sixteen
   informational responses are outside this supported behavior.
6. Correct schemas that used negative or unrepresentable string lengths.
   `additionalProperties:false` with no declared properties now rejects object
   members. The supported schema subset and byte-based string-length semantics
   remain unchanged.
7. Wait before reading final TaskGroup outcome statistics. Accepted work
   cancelled before execution counts as cancelled, including pool CancelPending;
   repeated waits do not count it twice. Running callbacks can poll either
   joined cancellation source. Cancellation remains cooperative, and a callback
   that returns normally still counts as completed. Logger Flush now reaches
   level-specific sinks as well as default sinks.
8. Keep build and test configurations aligned on multi-config generators. Retain
   FSXJ4 journals and their dependent witnesses at recorded locations with the
   producing version until recovery or cleanup finishes.

## Known limitations

- No new multi-file transaction, concurrent-writer/CAS guarantee, adversarial
  path sandbox, complete metadata fidelity or universal power-loss guarantee is
  introduced. Archive and download identity checks retain their documented
  filesystem boundaries.
- schemax remains an experimental subset, not complete JSON Schema. tuix remains
  an experimental foundation. Non-finite programmatic cfgx nodes still require
  caller rejection before serialization.
- ABI compatibility is not promised. Joined cancellation is cooperative and
  cannot preempt running user code.
- Validation is limited to the exercised platforms and configurations. The
  optional mbedTLS backend, 32-bit runtime checks and long fuzz campaigns were
  not newly executed by this functional verification. They are not silently
  counted as passing checks.
- Historical v0.3.3 archives, audit failures and v0.4 research material retain
  their original identities. This release makes no measured AI-adoption or
  workflow-cost claim and does not revive the stopped v0.4 plan.
