# ToolX v0.3.5

> Audience: ToolX consumers and maintenance reviewers
> Status: Released
> Applies to: v0.3.5
> Source of truth for: release narrative

Released on 2026-10-25. **This is the final manually maintained ToolX release.**
Manual bug fixes, security fixes, feature work and issue triage stop with v0.3.5.
The repository, documentation and historical artifacts remain available. Continued
use and future fixes are the responsibility of consumers or their forks.

## Highlights

- Check double-to-int64 and direct array-expansion limits before conversion or
  mutation; report buffered plain/encrypted save failures. Preserve INI scalar
  types and precision, remove obsolete keys and keep root keys before sections.
- Preserve INI quoted content and escaped key structure. Validate snapshot
  restores before publishing, and return errors for failed file/directory reads.
- Reject retained-backup and link source aliases before destructive operations;
  publish links only after successful creation and reject dangling tar paths.
  Extraction also preserves its input archive, hard-link aliases and ancestors.
- Respect HTTP total deadlines during retries and stalled uploads; saturate
  unrepresentable durations and release failed SOCKS-handshake sockets.
- Keep socket-write failures local to HTTP/TLS calls without changing process
  signal policy; reuse one OpenSSL BIO type index instead of consuming it per session.
- Escape every JSON log and CLI-diagnostic control character. Schema paths and inspector selection
  now escape special object keys using the existing cfgx path grammar.
- Preserve finite CLI doubles at round-trip precision before range checks;
  reject non-finite values, unit-scaling overflow and partially consumed numbers.
  `utils::parse::parse_double` also rejects embedded-NUL suffixes.
- Compare schema numeric bounds and mixed numeric enum entries without rounding
  int64 values to double. Adjacent integers above 2^53 and int64 endpoints no
  longer silently pass the wrong validation.
- Archive empty files and single-file sources with `include_root_directory`
  correctly. Copy each payload by its declared length and fail on I/O errors.
- Reject overflowing HTTP chunk declarations and body-budget violations before
  delivery, without rejecting legitimate large chunks under large limits.
- Allow zero/expired-deadline polling to observe futures that are already ready;
  preserve TaskGroup outcome accounting.
- Wake periodic log flushing during stop rather than waiting a whole interval.
- Isolate `toolx-http` and `toolx-log` audit and size-rotation paths from manifests,
  request bodies and input logs before writes or HTTP work. Reject ambiguous
  embedded-NUL audit boundaries and report log reading failures.
- Exclude local experiment runs, virtual environments and dependency trees from
  documentation fixtures and source archives, preserving official source fixtures.

## Compatibility

Public source signatures, thirteen library targets, six CLI products and existing
JSON envelope shapes are unchanged. These are correctness exceptions under the
[stability policy](../stability.md), not new product capabilities.

Rebuild consumers against matching headers and libraries: Logger now contains
additional synchronization state. ToolX does not promise ABI compatibility.
FSXJ4, existing journal migration requirements and default TLS/dependency choices
are unchanged.

## Build and dependency impact

C++20 and existing CMake requirements remain unchanged. No dependency or TLS
backend is added. Windows/MSVC passed all 44 CTest entries and Linux/GCC with
ASan/UBSan passed all 43. Installation, consumer and archive checks also passed;
the maintenance audit records the exact scope and final packaging-rule rechecks.
Formal release preflight verifies the Released documents against the v0.3.5 tag.

## Migration

1. Rebuild C++ consumers, including code using Logger. Do not mix old object files
   with the new private layout.
2. Expect CLI double strings to retain more significant digits. Correct callers
   that relied on the old six-digit rounding or acceptance of non-finite input.
3. Review schemas whose large integer bounds or mixed numeric enum entries were
   previously rounded. Newly reported violations reflect the actual values.
4. Keep audit outputs and their `.1`–`.5` default rotation destinations separate
   from HTTP manifests/body files and all log inputs. Conflicts now produce usage
   exit `2` before logging; use an ordinary, separate path without embedded NULs
   or Windows stream syntax.
5. Empty archive members and single-file roots now survive normal extraction.
   Regenerate tar files that were missing or conflicted with these members.
6. Zero-time waits can now return success for already-ready work. Running task
   cancellation remains cooperative and shutdown does not preempt sink callbacks.
7. INI saves quote strings and preserve double precision/types. Removed keys
   no longer reappear from an existing file, and added root keys remain at root.
   Matching quote delimiters inside quoted strings are doubled; backslashes
   remain literal. Escaped INI keys retain their structure. Do not rely on old
   type inference or stale assignments. Failed buffered saves
   now report errors; these APIs do not become atomic transactions.
8. Keep retained backup paths separate from replacement inputs. Link creation
   rejects self/alias destinations and preserves old destinations on failure.
   Tar extraction rejects dangling links instead of following them outside root.
   Overwrite also rejects input-archive aliases or destructive ancestor replacement;
   choose a separate extraction destination. Skip still consumes skipped payloads.
9. HTTP retries and upload writes honor the total deadline. Oversized positive
   timeout durations saturate safely. Custom transports/callbacks still own
   their execution time; DNS and other documented transport limits remain.
10. Treat schema/inspector paths as escaped cfgx paths; literal dots, brackets,
    backslashes, empty keys and the root marker no longer alias nested keys.
11. Restoring a snapshot must satisfy the reloader's validation rules. Validation
    failure leaves the active config, source trace and audit history unchanged.
12. Unresolved Windows junctions in audit boundaries fail before writes, even
    when a later step would create their target. Use separate, resolvable paths.

## Known limitations

- Verification is limited to the configurations actually recorded in the
  [maintenance audit](../development/audits/maintenance-20261025.md) and the
  immutable GitHub Actions runs for this release.
- Filesystem checks do not provide a new adversarial path sandbox, concurrent-writer
  guarantee or power-loss guarantee. Existing transaction and recovery limits remain.
- schemax and tuix retain their experimental boundaries. No full JSON Schema or
  Unicode grapheme-editing promise is added.
- The optional TLS backends, platform-specific privileges and sanitizer runs retain
  their individual executed or unexecuted status; they are not interchangeable.
